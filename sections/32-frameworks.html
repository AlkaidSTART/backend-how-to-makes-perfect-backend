框架选型

后端框架对比

学完分层之后，再单独横向看一遍框架：所有框架解决的都是同一件事——「HTTP 请求进来，怎么路由到处理函数、怎么取参数、怎么校验、怎么返回响应」。区别只在「框架替你做多少」。

把常见后端框架分成三类来对比，一一覆盖：

① TS/Node 后端框架 ② 全栈框架（前后端一体） ③ 跨语言对照：FastAPI / Gin

TS/Node 后端框架：两大家族

按「框架替你做多少」，TS/Node 后端框架可以分成两大家族：

微内核：路由 + 中间件

框架只管把请求接到处理函数，分层、校验、DI 都要自己搭。灵活，但架构靠自觉。

ExpressKoaFastifyHonoElysiaJS

全家桶：架构自带

Module、Controller、Service、DI 开箱即用，架构是框架给的。省心，但要接受它的约定。

NestJS
框架 一句话定位 类型体验 适合场景
ExpressNode 生态的「事实标准」，中间件最多、资料最全一般老项目维护、简单服务、学原理
KoaExpress 原班人马重写，async/await 洋葱模型一般想要更干净的异步中间件
Fastify主打高性能，JSON Schema 声明即校验良好性能敏感的 API 服务
Hono超轻量、多运行时（Node / Bun / Deno / 边缘）良好边缘函数、小而快的 API
NestJSAngular 风格的企业级全家桶，DI / 模块 / 装饰器优秀中大型后端、团队协作
ElysiaJSBun 专属极速框架，AOT + JIT 类型编译，150k+ RPS优秀Bun 运行时、追求极致性能与全栈类型安全
怎么选：个人学习 / 小工具，Express 或 Hono 随手写；性能敏感，上 Fastify；中大型业务系统，选 NestJS 这类自带架构的框架——它把本文档讲的分层、DI、模块化变成了开箱即用的默认。

全栈框架：Next.js / Nuxt / Remix

另一条路线是前后端一体：一个仓库、一个进程，前端框架直接提供「服务端接口」的能力，为的是 BFF（Backend For Frontend）和全栈一体化：

看到规律了吗：无论语言，后端都在做同一组事——路由、取参、校验（DTO）、分层（Controller/Service/Repository）、依赖注入、错误处理、统一响应。差异只在「语言有没有装饰器」「框架替你做多少」。

一句话记住

框架决定「代码长什么样」，架构决定「代码放在哪里」。
换框架只是换表达方式，分层、DTO、DI 这些思想哪个框架都能带走。
