分层篇

Controller

Controller 的职责：负责 HTTP 层。

例如：

Controller 主要负责：

HTTP Request
获取参数
调用业务
HTTP Response

Controller 不应该承担复杂业务逻辑。不推荐：

问题：

  • Controller 太胖
  • HTTP 与业务耦合
  • 数据库与 Controller 耦合
  • 难以测试
  • 难以复用业务逻辑

对比上面的 Express 写法，NestJS 的 Controller 每个方法体基本只有一行：调用 Service。取参数这件事被装饰器接管了：

@Controller / @Post / @Get

声明路由，不用手写 app.post(...)

@Body() / @Query() / @Param()

声明参数从哪来，框架自动解析 req

@RequirePermission(...)

权限声明贴在方法上，由守卫统一拦截

@ApiOperation / @ApiBody

顺带生成接口文档（Swagger）

真实项目的 Controller 依然很薄：贴装饰器 → 收参数 → 调 Service，HTTP 与业务依旧分离。
