参数校验

API 输入不能完全信任客户端。例如一个 email 字段，需要验证：

  • 是否存在
  • 是否是字符串
  • 是否符合邮箱格式
  • 长度是否合理

真实项目示例：NestJS 全局校验管道

真实项目用的是 class-validator：规则写在 DTO 上，校验管道在入口处全局注册一次：

每个字段的条件则贴在 DTO 上，例如岗位管理的 CreatePostDto：

  • 校验失败时请求直接被拦截，返回错误信息，进不到 Controller
  • whitelist: true：DTO 里没声明的字段自动剥掉——客户端多塞的 role、postId 不会透传到数据库
  • transform: true：自动把 query 里的字符串按声明类型转换
核心思想：API 边界必须进行输入验证。校验规则和 DTO 写在一起，校验动作由框架统一执行，业务代码里不再散落 if 检查。
